# AWS EC2 Instance Creation and IAM Policy Configuration Project

# Introduction
This project focused on creating and managing Amazon EC2 (Elastic Compute Cloud) instances while configuring IAM (Identity and Access Management) policies to securely control user access within the AWS environment. The goal was to gain hands-on experience in cloud infrastructure deployment and access control management using AWS services. EC2 provides scalable virtual servers in the cloud, allowing users to launch and manage computing resources on demand. By pairing EC2 with IAM, the project demonstrated how secure access and role-based permissions can be implemented effectively in a cloud ecosystem. This setup simulated a small-scale cloud environment suitable for testing, learning, and application hosting.

# Objectives
The objectives of this project were to:
1. Launch and configure an EC2 instance using the AWS Management Console.
2. Create and attach IAM users, groups, and roles with specific permissions.
3. Implement IAM policies to control actions such as viewing, starting, or terminating EC2 instances.
4. Explore security groups for network-level protection.
5. Understand the relationship between cloud infrastructure (IaaS) and identity management.

# Benefits
This project helped to achieve the following:
1. Providing practical exposure to AWS’s core services and cloud security fundamentals.
2. Helping to develop a deeper understanding of how cloud instances operate, scale, and interact with access control mechanisms.
3. IAM configuration demonstrated the principle of least privilege, ensuring users have only the permissions necessary to perform their tasks.
4. Working with EC2 also enhanced knowledge of instance types, AMI selection, and region-based deployment.
5. The project reinforced cloud administration concepts, including elasticity, high availability, and resource monitoring.
6. It helped to build a strong foundation for future roles in cloud engineering and cybersecurity.

# Challenges
A key challenge during the setup was ensuring proper IAM policy attachment to roles and users without granting excessive privileges. An overly restrictive policy initially caused limited access to instance management features. This issue was resolved by reviewing AWS documentation and using the AWS Policy Generator to craft a balanced, least-privilege policy. This challenge improved my understanding of permissions troubleshooting and network security management within AWS.

# Conclusion
Completing this project provided the following 
1. Valuable insight into cloud infrastructure management and secure access control on AWS.
2. Highlighted the importance of combining technical precision with security best practices when deploying and managing cloud resources.
3. Overcoming IAM and security group challenges reinforced practical skills in policy design and access troubleshooting.
4. The experience also emphasized how AWS services integrate seamlessly to provide scalable, secure, and manageable environments.

In conclusion, building and managing EC2 instances alongside IAM policies was a meaningful hands-on project that strengthened both cloud computing and security administration capabilities which is an essential skills for modern IT professionals.
